# Мастер персонажа D&D 5e 2014

Статический конструктор персонажа первого уровня с последовательной прокачкой 1→2→3. Учитывает зависимости расы, подрасы, класса, предыстории и черты, рассчитывает игровой лист и экспортирует JSON для Long Story Short. Лист 1–2 уровня, скачанный из Long Story Short, можно загрузить и довести до 3-го уровня. Черновик сохраняется в браузере.

## Публикация и приватность

Публикуйте только `index.html`, `robots.txt`, `favicon.ico`, `style.css`, `script.js`, `rules.js`, `creation-options.js`, `levelup-data.js`, `levelup-rules.js`, `levelup-ui.js`, `lss-export.js`, `lss-import.js`, `spell-info.js`, `wizard-steps.js`, `wizard-ui.js`, `config.json` и `img/`. Не размещайте в веб-каталоге `.git`, документацию, тесты и приватные файлы сервера. У приложения нет серверного хранилища персонажей: черновик находится в `localStorage` браузера пользователя. Копия загруженного листа LSS хранится там же, в отдельном ключе; «Создать нового героя» удаляет черновик и эту копию.

## Повышение уровня

На завершённом листе нажмите «Повысить до …». Мастер последовательно предлагает класс, хиты, решения класса и владения, магию и проверку изменений. Среднее значение кости или введённый результат учитывают Телосложение и бонусы за каждый уровень. Заклинания, инфузии, воззвания и заговоры изобретателя заменяются только в допустимых количествах и списках.

Заклинания выбираются в карточках с поиском, фильтрами и счётчиком; мини-лист остаётся рядом на компьютере и над шагом на телефоне. Подпись среднего показывает полную прибавку хитов с Телосложением и бонусами.

Мультикласс проверяет характеристики всех имеющихся и нового класса, включая постоянные бонусы. Новый класс даёт только положенные владения и свои решения первого уровня; снаряжение, монеты и начальные спасброски не выдаются повторно. Можно повысить любой из имеющихся классов или взять третий в пределах общего уровня 3. Обычные ячейки суммируются по правилам мультикласса, Магия договора остаётся отдельной; доступные заклинания и квоты подготовки определяются уровнем каждого класса.

Пока не нажата кнопка применения, исходный герой сохраняется. Перезагрузка продолжает отдельный черновик повышения; отмена убирает только этот черновик. Для редактирования исходных решений после прокачки необходимо подтвердить сброс уровней в диалоге страницы. Повреждённый журнал не даёт хитов, умений или экспорта и сохраняется до явного исправления/сброса.

Поддержаны все 13 классов и 118 официальных legacy-подклассов до 3-го уровня. Каталог содержит 213 заклинаний кругов 0–2 с источниками, требованиями и отдельными квотами книги, подготовки, известных и автоматически выдаваемых заклинаний. Все ячейки передаются по кругам, Магия договора хранится отдельно. Не поддерживаются 2024, UA, сторонние материалы и повышение до 4-го уровня. Перечень книг, правила отбора и границы проверки описаны в [аудите каталога](docs/levelup-audit.md).

Вариантные особенности TCE включаются явно; заменяемые особенности не складываются. Формы животных/духов, модель доспеха, вид пушки, лунная фаза и формы договора остаются решениями применения и отдыха. У каждого ресурса в листе и экспортируемом тексте сохраняются число применений и восстановление. Нативная схема редактируемых счётчиков ресурсов LSS требует дополнительной проверки импортом; текст является проверенным способом сохранения этих данных. Неизвестные карточки заклинаний передаются текстом с явной отметкой о ручном добавлении.

`robots.txt` и мета-тег `noindex` просят поисковых роботов не индексировать сайт. Они не ограничивают доступ: любой, кто знает адрес публичного сайта, может скачать его статические файлы. Для закрытого доступа нужна авторизация на уровне веб-сервера или роутера.

## Запуск

Нужен Node.js 20 или новее. Устанавливать пакеты не требуется.

```sh
npm start
```

Откройте [127.0.0.1:8000](http://127.0.0.1:8000/). Сервер слушает только локальный адрес. Для публикации достаточно статического хостинга; `file://` не поддерживается из-за загрузки `config.json`.

```sh
npm run check
```

Команда проверяет воспроизводимость каталога, синтаксис всех модулей и запускает тесты правил, интерфейса и экспорта. CI выполняет ту же проверку.


## Воспроизводимая сборка каталога повышения

`npm run catalogue:build` создаёт `levelup-data.js` из проверенных локальных снимков в `docs/catalogue-sources/`. `npm run catalogue:check` сверяет SHA-256 входов и точные UTF-8/LF байты результата, не изменяя файлы. Эта проверка входит в `npm run check` и CI; сборка, проверка и `node docs/enrich-companions.cjs` работают без сети и независимо от текущего каталога запуска.

Начальные метаданные 5etools закреплены на коммите `b9061583536101068b3a59d27e886d1fa664e366`. Названия, ссылки и дата аудита 2026-10-03 перенесены из исходного коммита проекта `fb2fa5d68f9acf702f51538542213efc96c7c745`: исторический HTML dnd.su не восстанавливался. Происхождение и реальные хеши загруженных ответов записаны в манифесте; подробности — в [аудите каталога](docs/levelup-audit.md#воспроизводимые-источники).

Обновление источников выполняется отдельно, с полным SHA и явной датой нового аудита:

```sh
npm run catalogue:update -- --revision b9061583536101068b3a59d27e886d1fa664e366 --date 2026-10-09
npm run catalogue:build
npm run check
```

Первый шаг обращается к закреплённому upstream и текущим индексам названий dnd.su. Снимки заменяются только после успешной загрузки, разбора и пробной генерации; при ошибке предыдущий набор остаётся доступен. Перед принятием обновления проверьте изменения снимков, манифеста и каталога. Ветки и короткие SHA отклоняются до сетевых запросов; обычная сборка никогда не обновляет источники.

## Порядок создания

Класс → раса → предыстория → характеристики → умения, снаряжение и магия → образ → итоговые владения.

- 13 классов, 50 рас с обязательными подрасами, 14 предысторий.
- Стандартный набор, покупка за 27 очков или ввод результатов бросков. Бонусы расы и черты считаются отдельно.
- Подклассы первого уровня, боевой стиль, особенности следопыта, 42 черты PHB для вариантного человека.
- Стартовое снаряжение класса и предыстории, монеты, надетые доспехи и щит, атаки и КД.
- Известные/подготовленные заклинания, книга волшебника, доменные и расовые заклинания, магия черт.
- Владения от всех источников со списками допустимых вариантов, компетентность и замены повторных навыков/инструментов.
- Хиты, скорость, ограничения полёта, инициатива, спасброски, модификаторы всех навыков и пассивное Восприятие.
- Поиск рас, переходы к предыдущим этапам, автосохранение и проверка всего персонажа перед экспортом.

Выбор владений находится в конце, когда известны все источники. Заранее выданные варианты отмечены в списках. Повторные фиксированные навыки и инструменты создают выбор замены того же типа. После изменения раннего шага устаревшие слоты удаляются с сообщением, а конфликты в оставшихся выборах требуют исправления.

## Экспорт в Long Story Short

На итоговой карточке нажмите **«Скачать JSON для Long Story Short»**. В [списке персонажей сайта](https://longstoryshort.app/characters/list/) откройте **`.json` → «Загрузить .json»**, выберите файл и подтвердите загрузку.

Это нативный контейнер LSS v2 для редакции 2014 с вложенным сериализованным листом, а не дамп внутреннего состояния мастера. Формат исследован по настоящему экспорту сайта. Подробности проверки: [docs/lss-format.md](docs/lss-format.md).

Заклинания, отсутствующие в каталоге карточек LSS, сохраняются текстом с источником и ограничениями. Перед экспортом мастер перечисляет их: такие карточки потребуется добавить на сайте вручную.

## Загрузка листа из Long Story Short

Лист, скачанный из Long Story Short, загружается кнопкой **«Загрузить из LSS»** в шапке. Файл читается в браузере и на сервер не отправляется. Загрузка заменяет текущий черновик; если в нём уже есть данные, мастер предупреждает об этом до начала проверки.

Скачать лист можно двумя способами:

- один персонаж — через его меню в LSS;
- все персонажи сразу — **.json → Скачать .json** в списке персонажей.

Принимаются оба файла. Если в файле несколько персонажей, выберите одного. Персонаж, которого нельзя импортировать (например, 3-го уровня — «пока не поддерживается»), показан в списке с причиной и не выбирается. Файл больше 2 МБ текста отклоняется.

Поддерживаются листы **1-го и 2-го уровней** редакции 2014. Лист без определимого уровня, с повреждёнными данными или с уровнем, который не совпадает с суммой уровней классов, не импортируется: мастер просит исправить его в LSS и скачать заново. Если LSS отмечает лист редакцией 2024, мастер показывает предупреждение и работает по правилам 2014: редакция в настройках аккаунта LSS правила не определяет.

**Проверка распознанного.** Экран проверки делится на два блока: **«Распознано»** и **«Проверьте и выберите»**. Пункты второго блока с полем, которое ещё не проходит проверку мастера (неоднозначные совпадения, сокращения, отсутствующие выборы), также видны в плашке над шагами: закрытые пункты из неё исчезают, а больше шести сворачиваются в «и ещё N». Пункты без поля мастера (например, редакция листа) показываются только на экране проверки. Шаги проходят обычную проверку мастера.

**Что распознаётся автоматически.** Класс, подкласс 1-го уровня, раса и подраса, предыстория, мировоззрение, характеристики (способ определяется по значениям: стандартный набор, покупка или вручную), имя, возраст, рост, вес, черты личности, идеалы, привязанности, слабости, описание, владения, которые подтверждает лист. Заклинания распознаются только у персонажей с одним классом; у мультикласса их выбираете в мастере. Каждый пункт отчёта помечен как **распознано**, **проверьте** или **выберите**.

**Что выбираете вы.** В листе LSS нет выборов создания, поэтому стартовое снаряжение выбирается заново. Выборы, которых нет в листе, остаются пустыми; заклинания мультикласса тоже выбираются в мастере. Инвентарь из листа при выгрузке сохраняется.

**Восстановление 2-го уровня.** Для листа 2-го уровня после проверки первого уровня на итоговом экране рядом с «Повысить до 2-го уровня» появляется кнопка **«Восстановить 2-й уровень из листа»**. Она открывает обычный мастер повышения, предзаполненный подклассом, заклинаниями, воззваниями и стилем боя, которые подтверждает лист. Хиты берутся из разницы `hp-max`: если бросок определяется однозначно, он подставляется, иначе — среднее значение. Кнопка доступна, если класс второго уровня распознан и текущий класс совпадает со стартовым классом листа. Иначе открывается обычное повышение с пометкой «Выборы из листа не подобраны — выберите их вручную». Если подобрать выборы не удалось, тоже открывается обычное повышение с пояснением.

Пока уровень не восстановлен, скачивание и копирование JSON заблокированы, а блок «Данные для экспорта» скрыт: иначе в LSS попал бы персонаж ниже исходного уровня. Хиты, подобранные по листу, отмечены пометкой «Хиты подобраны по листу LSS»; пометка исчезает, как только вы меняете хиты вручную.

**Что сохраняется в выгрузке.** Выгрузка объединяет сгенерированный лист с исходным:

- из исходного листа: имя, раса, предыстория, мировоззрение, имя игрока, опыт, возраст, рост и вес (если заполнены в LSS); монеты, ресурсы, состояния, настроенные предметы; все текстовые блоки LSS, кроме «Владений», «Черт» и «Атак» (заметки, снаряжение, инвентарь и т. п.); ваши строки оружия и бонусы; пользовательские карточки заклинаний; временные хиты и спасброски от смерти; прочие данные листа, которые мастер не знает;
- текущие хиты: сдвигаются на прирост максимума и ограничиваются пределами от 0 до нового максимума. Если текущих хитов больше 0, состояние «при смерти» и спасброски сбрасываются; при 0 хитах исходное состояние сохраняется;
- КД и скорость: значение из листа, если вы его меняли в LSS (то есть отличается от расчёта мастера на исходном уровне). Если оно при этом расходится с текущим расчётом мастера, в «Черты» добавляется строка «Проверьте КД: …» или «Проверьте скорость: …». Иначе берётся расчёт мастера, поэтому скорость, которая растёт с уровнем, обновляется;
- оружие: строки листа без изменений. Из расчёта мастера добавляются только заклинания-атаки. Строки оружия из стартового комплекта мастера в лист, созданный не мастером, не попадают. Для листов, которые выгружал сам мастер, добавляются все строки оружия, как и раньше;
- пересчитываются мастером: характеристики, владения, спасброски, навыки, особенности, атаки, ячейки и заклинания из каталога LSS.

Текстовые блоки «Владения», «Черты» и «Атаки» собираются так: сначала текст мастера, затем строка **«— Из загруженного листа LSS —»** и ваши абзацы из исходного блока. Повторная выгрузка не дублирует текст. Строки, похожие на строки самого экспорта («Языки: …», «Ячейки: …», «Умение 2-го уровня: …»), которые стоят **до** маркера, считаются текстом мастера и не переносятся. После маркера ваши строки сохраняются, кроме точных копий текста мастера. Оружие, удалённое на сайте, вернётся, если мастер его создаёт.

Пользовательские карточки заклинаний переносятся только для листа редакции 2014. Проверенные файлы LSS, в том числе прегены 2014, помечены 2024. Поэтому такие карточки на практике нужно добавить в LSS заново. Текст и инвентарь сохраняются в любом случае.

**Копия листа в браузере.** Исходный лист хранится отдельно от черновика, под ключом `dnd-character-draft-v2:lss-original`, и связан с импортом меткой времени. Кнопка «Создать нового героя» удаляет и черновик, и эту копию.

- Если браузер не может сохранить копию (нет места или хранилище недоступно), объединение работает до перезагрузки страницы, и мастер об этом сообщает.
- Лист больше примерно 1 МБ в браузер не сохраняется. Выгрузка тогда идёт без заметок и снаряжения из LSS, и мастер предупреждает об этом.
- Если копия утрачена, мастер предлагает **«Прикрепить исходный лист»**. Персонаж при этом не меняется: уровень, журнал и выборы остаются как есть, а выбранный лист сверяется по имени и уровню (при другом имени мастер спрашивает подтверждение; лист другого уровня и слишком большой лист не принимаются).

**LSS создаёт нового персонажа.** Импорт файла в LSS добавляет персонажа, а не обновляет старый. Сверьте новый лист со старым и удалите старый вручную.

**Проверка.** Загрузка, распознавание, восстановление 2-го уровня, блокировки выгрузки, хранение копии и слияние покрыты автоматическими тестами (`npm run check`). Проверено в браузере 15.10.2026: загрузка двух родных листов 1-го уровня (варвар, друид), проверка мастера и повышение варвара до 2-го уровня с выгрузкой, файл с несколькими персонажами и лист 3-го уровня, ширина 375 px. Реальный импорт объединённого файла обратно в LSS в этом выпуске не выполнялся. Подробности и границы проверки — в [docs/lss-format.md](docs/lss-format.md).

## Границы правил

Один или несколько классов, общий уровень 1–3, редакция **2014**, с конкретными legacy-версиями рас из дополнений. Подклассы и заклинания включают официальные книги legacy; изобретатель использует TCE. Дополнительные книги, вариантный человек и черты требуют согласования с Мастером.

Приложение не поддерживает уровни от 4-го, правила 2024, произвольные домашние правила, собственную предысторию и закупку инвентаря вместо стартового комплекта. Условные боевые эффекты приведены в примечаниях; временные состояния не включаются в постоянные показатели автоматически.

## Архитектура

| Файл | Назначение |
|---|---|
| `config.json`, `config.schema.json` | Каталог, тексты и порядок страниц |
| `rules.js` | Расчёты ASI, владений, конфликтов и производных чисел |
| `creation-options.js` | Выборы первого уровня, снаряжение, черты, заклинания |
| `levelup-data.js`, `levelup-rules.js`, `levelup-ui.js` | Каталог официальных вариантов, журнал повышения и мастер 1→2→3 |
| `lss-export.js` | Адаптер нативного JSON Long Story Short и слияние с загруженным листом |
| `lss-import.js` | Чтение листа LSS, распознавание 1–2 уровня и восстановление 2-го уровня |
| `script.js`, `wizard-steps.js` | Состояние, валидация, интерфейс и сохранение |
| `wizard-ui.js` | Шаги с итогами, лист персонажа, карточки рас и характеристик |
| `spell-info.js` | Школа, дистанция и краткое описание заклинаний первого уровня |
| `style.css`, `img/` | Оформление и локальные изображения |
| `test/`, `tests/` | Регрессионные и матричные тесты |
| `dev-server.js` | Локальный сервер без зависимостей |

В конфигурации справочные ссылки разрешены только по HTTPS на `dnd.su`, изображения — из локальной папки `img/`. Пользовательские поля вставляются как текст, без HTML. В LSS они передаются как узлы rich-text документа.
